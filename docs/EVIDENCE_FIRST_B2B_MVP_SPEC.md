# Evidence-First B2B MVP Specification

The full local `307/307` objective and its non-negotiable invariants are canonical in [FULL_307_EVIDENCE_INFRASTRUCTURE_GOAL.md](FULL_307_EVIDENCE_INFRASTRUCTURE_GOAL.md). This document specifies the B2B Evidence Passport implementation boundary within that objective.

## Objective

Deliver a complete local-only professional legal-intelligence collection for every one of the 307 canonical GEO without changing Legal Truth, Store Truth, coordinates, map colours, SEO, production, billing or outreach. A verified source-metadata correction is permitted only when the retained source record itself proves that a quote or annotation was copied from a different jurisdiction; it must preserve the source URL/owner, leave the legal conclusion unchanged, and regenerate every derived projection.

The complete local workflows are:

1. **Evidence Passport collection** — a versioned record for each of the 307 canonical GEO with the current conclusion, retained official citations, rule/scope, review information and an honest history boundary. It exports deterministic JSON and print/PDF documents for every canonical GEO.
2. **Full-universe Change Monitor / Watchlist** — a read-only view over the immutable 307-GEO canonical-projection snapshot ledger that keeps source events, pending review and canonical legal-conclusion changes as three distinct classes.
3. **Delivery boundary** — read-only JSON export and a script-free local embed card for every Passport. Bulk generated documents remain outside the repository or disposable build output; `data/b2b_evidence/evidence_delivery_manifest.json` is the committed deterministic manifest retaining every artifact hash and canonical projection identity.

## Canonical data contract

- The current conclusion is read exclusively from the committed Truth Map feature projection used by the map, rich popup and in-place SEO panel.
- The retained source ledger may add source provenance only. It cannot determine, change, downgrade or promote a legal conclusion.
- A Passport must retain every map/popup/SEO citation exactly. Additional retained official source records must be labelled as extensions, never as a different current conclusion.
- A jurisdiction-specific official fragment and annotation must belong to the same official URL and owner GEO. A metadata fingerprint repeated under distinct official URLs and owner GEOs is a source-record defect, not a legal conclusion or a reason to fall back to another territory; the canonical record is corrected from its retained direct evidence before it may be shown.
- The local collection begins with one current versioned canonical baseline. It must report the absence of a prior canonical comparison baseline rather than infer legal-conclusion history from legacy map, SEO, SSOT or profile data. A later snapshot is appended only from a real canonical projection version; equal versions create no legal-conclusion event.
- A legal-conclusion change event requires two canonical projection versions and a changed current legal colour or rule. An SSOT status, source availability, URL redirect, profile edit or legacy colour is never such an event.

## Change-event classification

| Class | Meaning | May change the current conclusion? |
| --- | --- | --- |
| `SOURCE_CHANGE` | Retained official source content, owner or final URL changed. | No — human semantic review is required. |
| `PENDING_REVIEW` | Source needs semantic/visual/effective-date/access review. | No. |
| `CANONICAL_LEGAL_CONCLUSION_CHANGE` | Two canonical versions differ in legal colour or rule. | It reports an already-published canonical difference; it does not create one. |

Every source/pending event opens an immutable review case keyed by GEO, source URL, event kind, revalidation state and change reason; the operation ID also binds its initial signal identity. Each later C1 check of that same signal appends a provenance-bound attempt and updates neither the operation nor its resolution. A genuinely different content/final-URL/access/hash/owner/applicability identity normally opens a new operation. The sole bounded migration exception is an incomplete V1 owner/applicability identity: schema-v6 preserves that V1 attempt and appends exactly one corrected V2 attempt to the same unresolved operation; if the V1 operation was already resolved, the V2 identity opens a new operation. Resolution coverage is exact-signal only: a later return to another historical signal, including the earlier V1, opens a new deterministic operation and never inherits closure. C1 reachability, HTTP 304, byte equality, a redirect or a newer fetch state can never close semantic, effective-date, visual, applicability or source-change review. A resolution is appended only after an explicit human evidence review and must retain reviewer identity, the exact reviewed attempt and signal identity, a GEO-linked official evidence URL, note and real close time that is not materially in the future. Before close, the sole resolver validates the entire schema-v6 registry and recomputes every current payload, preimage, attempt identity and hash. Latest selection uses the attempt-ID-bound source checked-at, not mutable classifier `attemptedAt`; an equal-check tie is valid only for the exact payload-equivalent V1-missing-owner/applicability → V2-corrected migration, otherwise it is ambiguous and fails closed. Every resolution must bind that semantic latest attempt. Builder and resolver share the same exclusive owned lock, staged durability write, intended-stage hash recheck, exact-preimage compare-and-swap and atomic rename. Builder holds exact canonical reconciliation and canonical-GEO input snapshots through commit. Resolver parses the exact official-domain and ownership-registry snapshots once and holds both unchanged through validation and every commit, regardless of evidence URL relation. Future-dated, stale, staged-byte-tampered, concurrent, cross-operation or non-latest state fails without replacing bytes, and a foreign lock is preserved. Canonical camelCase/snake_case owner and applicability aliases must normalize to the same values or fail closed. `CONFIRMED_CURRENT` and `SUPERSEDED` remain source-review outcomes only; neither is a finding that the law is current and neither changes Legal Truth. An explicitly resolved current signal leaves the active Source/Pending queues but remains permanently visible in append-only history. Accounting or classifying an operation as `ACCESS_BLOCKED`, `APPLICABILITY_UNRESOLVED` or `CANONICAL_REVIEW_REQUIRED` leaves it open and must never be reported as human closure or `307/307` legal currency.

## Legal value and honesty for every GEO

- Every Passport must show, as separate facts, the current Legal Truth conclusion and any map-display research direction. Display colour is never allowed to strengthen, replace or conceal an `UNKNOWN` legal conclusion.
- Every current legal assertion retains its official source owner, territorial applicability, rule/scope, legal effective state, direct quotation or bounded annotation, source check date/access state and confidence. A missing check date, network error, redirect, profile edit, translation or coordinate failure is never a legal conclusion.
- The source-freshness presentation states what was checked, retained source changes, pending semantic/visual/effective-date reviews and canonical legal-conclusion changes as distinct facts. It begins with one honest baseline and labels the absence of history rather than reconstructing it from legacy layers.
- The public-ready local **Source Freshness Passport** retains four separate timestamps where available: source checked-at, source-change detected-at, review opened-at and canonical legal-conclusion published-at. A missing timestamp remains `NOT_RECORDED`; it must not be invented from a file modification time, legacy layer, fetch attempt or runtime `/api/build-meta` fallback without an immutable deployment receipt.
- Store Truth presentation must explain saved-but-unmapped records through grouped fail-closed gate categories: legal/store-type eligibility, lifecycle, official address, exact authoritative coordinate and official source. It must not disclose a hidden precise location, infer operating status or represent a blocked record as proof that no store exists.
- The public-ready local **Why no leaf?** page uses those grouped reasons and visible counts only. It must never turn an absence of a leaf into an assertion that no cannabis business exists in the territory.
- A standard correction request lets a business submit a licence or official source as an untrusted candidate with receipt, provenance, review and outcome state. It cannot alter a current conclusion, source ledger, Store record, coordinate, eligibility, leaf, map position or ranking until independently verified through the canonical legal and Store Truth gates.
- The public-ready local **professional changelog** records event time, GEO, old/new evidence identity and class. `SOURCE_CHANGE` and `PENDING_REVIEW` are explicitly non-legal events; only `CANONICAL_LEGAL_CONCLUSION_CHANGE` records the separately dated canonical publication and prior/current rule or colour.
- Localisation may publish a legal assertion only after editorial review. It retains the original official citation, source-language fragment, scope and disclaimer. Machine translation may prepare a draft but cannot publish, simplify an exception or replace a retained source.
- Exact Watchlist is end-to-end: a noncanonical GEO is rejected in both UI and API and must never silently widen to all 307 GEO.

## Product and commercial invariants

- Current legal status, material restrictions and primary official links are free. No safety finding is paywalled.
- No customer may buy a leaf, ranking, map position or `verified` badge. Store Truth remains fail-closed and independent.
- A Weedmaps-style commercial directory, lead list or scraped business listing is not a legal or Store Truth source.
- The public production map receives no AI/Social retention feature through this initiative; audit-only route isolation remains intact.
- No Google Ads acquisition motion may begin before a written policy assessment approves the exact copy, destination and geography. Google’s current policy bars ads facilitating recreational drug use and gives only limited, specific cannabis-related exceptions. [Google Ads policy](https://support.google.com/adspolicy/answer/16489299?hl=en)
- No Stripe or other billing integration may begin before a written, provider-specific classification of the exact isLegal legal-intelligence business model. Stripe’s current restricted-business policy explicitly lists marijuana products, dispensaries and related businesses. [Stripe policy](https://stripe.com/legal/restricted-businesses)
- Pricing, account provisioning, payment collection, sales outreach, production deployment and commercial data licensing are separate future authorisations.

## Local-route boundary

- The UI lives below `/truth-map/evidence-passport`; the existing proxy returns `404` for every `/truth-map/*` path on non-local hosts.
- The delivery APIs verify the request host themselves because proxy does not match `/api/*`. Non-local hosts receive `404` before a local projection is loaded.
- JSON responses use `Cache-Control: no-store`. The embedded document is script-free, `noindex,nofollow`, and carries the current/free/no-paid-placement boundary.
- A Watchlist may select only canonical GEO identifiers through repeated `geo` parameters or the comma-separated `watch` parameter. Identifiers are uppercased, deduplicated and sorted; an unknown value returns `400` and is never silently widened or mapped to a different jurisdiction.
- `/truth-map/evidence-passport/review` and `/api/truth-map/b2b/source-review` are the local read-only Source Review Workbench. Schema v3 classifies each operation as current active, historical open or explicitly resolved, exposes the complete ordered attempt history plus exact close tokens derived from the same registry bytes, and for current sources shows only the retained owner/applicability, fragment, current/effective, visual/screenshot, evidence-scope and confidence fields. It independently recomputes the current canonical V2 signal identity and fails closed if the selected latest attempt is missing or stale. Missing fields remain `NOT_RECORDED`; cross-source inference is forbidden. It caps an unfiltered response at 100 dossiers and accepts only `geo`, `category`, `state=current|historical|resolved|open` and an exact `operationId`. The API has no write handler and every non-local request returns `404`.

## Acceptance

- Exactly `307/307` Passports resolve from the static public projection and the retained canonical source ledger; every GEO has deterministic JSON, print/PDF and script-free embed delivery represented in a manifest with its projection version and content hash.
- For each GEO, current status, summary and map/popup/SEO citations equal the selected Truth Map feature properties.
- The source ledger, matrix, final projection and Passport have zero cross-jurisdiction fragment-plus-annotation collisions across distinct official URLs and owner GEOs.
- Change Monitor proves its three event classes with pure tests and has no false canonical legal-change event when only one baseline exists; a controlled two-version fixture proves the all-GEO comparator reports only a changed canonical conclusion.
- An explicit Watchlist retains exactly the requested canonical GEO set in both the local UI and read-only monitor API; the mandatory browser smoke demonstrates a multi-GEO selection.
- Delivery APIs are read-only and local-only; non-local API requests return `404`.
- Source Review Workbench accounts for the complete 307-GEO universe, keeps current and historical operations separate, and proves invalid/duplicate/empty filters fail closed. Every current attempt payload and identity is independently recomputable; legacy missing fields are explicit. A controlled resolution fixture removes exactly one operation from the active Passport/Monitor projection while retaining its append-only history.
- Publication, correction-review and editorial-localisation writers prove exact-byte compare-and-swap, foreign-lock preservation and rejection of concurrent, stale or tampered writes. Controlled fixtures prove one receipt-backed canonical change, one same-GEO correction handoff and `DRAFT -> APPROVED -> SUPERSEDED` publication semantics without changing Legal Truth or Store Truth.
- Full local regression has zero mandatory smoke failures/skips and the root receipt contains `POST_CHECKS_OK=1` and `HUB_STAGE_REPORT_OK=1`; bulk documents are not retained in the repository.

## Local implementation map

- `apps/web/src/truth-map/evidencePassport.ts` builds all 307 deterministic Passports and their script-free embed and print/Save-as-PDF representations.
- `apps/web/src/truth-map/evidenceDeliveryManifest.ts` binds every JSON, embed and print representation to the canonical projection version and SHA-256 identity.
- `data/b2b_evidence/canonical_projection_ledger.json` contains the single honest 307-GEO baseline. A later append requires a real publication receipt and exact ledger preimage: `npm -w apps/web run evidence:snapshot -- --published-at=<canonical-UTC-ISO> --commit-sha=<exact-40-hex-SHA> --build-id=<immutable-build-id> --actor=<publisher-id> --expected-ledger-sha256=<exact-current-ledger-sha256>`. It accepts only a different real canonical version with a publication time strictly newer than the previous recorded publication, binds that version to the receipt, validates the complete 307-GEO universe, rejects equal-version/date-only/stale/cross-version input and any tampered receipt or snapshot hash, then commits under an exclusive lock with staged exact-byte compare-and-swap plus atomic rename. Reload validates every later receipt against the SHA-256 of the exact canonical serialization of all preceding snapshots, so a false history prefix cannot be legitimized by re-sealing the last receipt. Passport and Change Monitor read that append-only history; a later canonical-difference event uses the receipt-backed current-version publication time rather than an inferred file or build date.
- `npm -w apps/web run evidence:manifest` deterministically writes `data/b2b_evidence/evidence_delivery_manifest.json`; the full root cycle regenerates it after source-review operation classification and tests byte-for-byte parity with the runtime manifest.
- `apps/web/src/truth-map/changeMonitor.ts` and the local changelog surface preserve the three event classes and use `NOT_RECORDED` whenever a distinct event timestamp does not exist.
- `apps/web/src/truth-map/sourceReviewWorkbench.ts`, `/truth-map/evidence-passport/review` and `/api/truth-map/b2b/source-review` provide the bounded local read-only operations view. Schema v3 returns the SHA-256 of the exact registry bytes used for the dossiers, the complete ordered attempt history, exact `operationId` lookup, copy-ready close tokens and the recorded current-source C2/C3 evidence fields; it never performs a resolution or infers absent metadata.
- `data/b2b_evidence/source_review_operations.json` is the append-only schema-v6 source-review operations, attempts and explicit human-resolution registry. Current attempts use canonical `SOURCE_REVIEW_SIGNAL_V1` or corrected `SOURCE_REVIEW_SIGNAL_V2` payloads with recomputable SHA-256 and exact identity preimages. V1→V2 is append-only and may change only owner/applicability from missing to the canonical recorded values; all other fields must remain identical. A legacy attempt whose source fields were not retained is explicitly `LEGACY_SIGNAL_DETAILS_NOT_RECORDED_V1`; missing values remain `NOT_RECORDED` rather than being reconstructed. `tools/review/build_source_review_operations.mjs` classifies every current source/pending/freshness signal, appends each real C1 attempt and retains earlier operations and identifiers without auto-resolving them. `tools/review/resolve_source_review_operation.mjs` is the only normal close path and requires `--human-reviewed` plus reviewer, evidence, note, outcome and real close-time provenance; it binds the resolution to the exact latest attempt/signal and accepts only the retained source, its exact revalidated final URL or an official-domain/ownership-SSOT URL for the same GEO.
- The explicit close command is `node tools/review/resolve_source_review_operation.mjs --human-reviewed --operation-id=<id> --reviewed-attempt-id=<latest-attempt-id> --expected-signal-identity-sha256=<signal-sha256> --expected-registry-sha256=<exact-registry-file-sha256> --reviewer-id=<reviewer> --evidence-url=<https-official-evidence> --note=<review-note> --outcome=<CONFIRMED_CURRENT|SUPERSEDED> --resolved-at=<ISO-8601> --resulting-state=<reviewed-state> --resulting-reason=<reviewed-reason>`. A missing or stale identity/provenance field fails closed without changing registry bytes; the command cannot change Legal Truth or Store Truth.
- `apps/web/src/truth-map/storeLeafTransparency.ts` provides aggregated, non-location-bearing Store-gate explanations for the complete canonical GEO universe.
- `apps/web/src/truth-map/correctionRequest.ts` writes only untrusted append-only local receipts and separate assignment/decision/outcome events under `cache/b2b/`. Every event append is exact-review-bytes CAS guarded with fixed lock ordering, staged write, file/directory durability sync and atomic rename; only exact-owner stale artifacts may be recovered, while foreign locks remain untouched. After `APPROVED_FOR_MANUAL_HANDOFF`, `HANDOFF_RECORDED` revalidates the receipt/candidate and source registry at commit time, then binds the candidate hash only to an existing unresolved same-GEO source-review operation and exact source-registry bytes SHA-256. An identical retry is idempotent, while stale, conflicting, missing, resolved-target, cross-GEO or pre-approval handoff fails before mutation. No stage can promote legal, Store, coordinate, leaf, map-position or ranking state.
- `data/b2b_evidence/editorial_localisations.json` is the append-only schema-v2 fail-closed editorial event registry. `npm -w apps/web run evidence:localisation -- --action=<draft|approve|supersede> ... --expected-registry-sha256=<exact-current-registry-sha256>` is local-only and appends under an exclusive owned lock with staged exact-byte compare-and-swap plus atomic rename. The same local read API provides no-write preparation payloads for a draft by GEO and for approval by localisation ID, deriving exact registry, Passport, citation, fragment, scope and disclaimer identities from one read. Every event has a deterministic event ID/content hash and `previousEventSha256`; localisation IDs are globally unique, and broken, duplicate or tampered chains are invalid. A `DRAFT` never publishes; only a current `APPROVED` event bound to the exact GEO/assertion, retained citation identity, original fragment hash, current Passport version/payload hash, scope/disclaimer hashes and editor/time is returned by the API; a `SUPERSEDED` approval no longer publishes. If Passport/citation/fragment/scope/disclaimer identity later drifts, that approval is omitted fail-closed until a new editorial approval. The actual approved set remains honestly empty until a real editor completes that gate.

Static implementation is complete. Runtime and whole-project acceptance are separate gates and must not be inferred from focused tests, lint, TypeScript or build success.
